I happened upon my old GitHub Pages experiment. It looks terrible—especially compared to my newer work. Later that day, I read [Mathieu's blog](https://mropert.github.io/), which only reinforced the certainty that I would *not* sleep well tonight.

Guilt, you see. Tech guilt. It's like technical debt, except you can't sleep it away.

(I'm kidding. Nobody sleeps technical debt away. We put it in a Jira ticket, and six months later someone closes it as *Won't Fix*.)

### What Mathieu Teaches Us

Visually, Mathieu's blog is unapologetically utilitarian—pure late-2010s developer minimalism. Structurally, though, it nails everything an engineering blog actually needs:

- **Zero clutter:** A single readable column, clear dates, topic tags, and direct excerpts.
- **Fast static output:** No client-side framework bloat, no cookie banners, no scripts fighting the reader.
- **First-class RSS:** Proper feed support out of the box, so anyone using a feed reader can subscribe without checking back manually.

That became the baseline: keep the structural discipline and full-text RSS, ditch the 2023 hand-rolled HTML relics (`public/` committed to Git, leading spaces in favicon paths, unmaintained templates), and rebuild on a clean, tested Hugo pipeline.

### Picking an Aesthetic Without Over-Engineering It

A single-column static blog solves structure, not taste. Before writing a line of CSS, I narrowed the visual direction down to five candidates:

- **Dune (Caladan / Arrakis):** Storm-sea slate and forest green, or sandstone and ochre. Memorable and literary, though slightly theatrical for a personal engineering notebook.
- **Flying Fortress Games (FFG):** Aviation-blueprint hairlines and muted steel/brass. Clean, except I already run a separate site for the studio—blurring personal systems notes with game-dev branding defeats the point of keeping identities separate.
- **IBM ThinkPad:** Matte carbon surfaces, `IBM Plex`, and a single TrackPoint-red accent. Zero fluff, industrial, and honest to the hardware I actually type on.
- **1950s Discipline (Swiss / Braun):** Strict asymmetric grid, exposed `1px` rules, archival paper and carbon ink, and one signal accent. Timeless, legible, and immune to web design trends.
- **2026-Engineer:** High-contrast slate, crisp sans-serifs, and monospace code blocks. Familiar and friction-free, though dangerously close to looking like every other developer template on GitHub.

Full disclosure: I already indulged the Dune angle elsewhere—my GRUB theme is an Atreides setup (built around a Gemini-generated image), and my Oh My Zsh theme is called *Caladan* ([GRUB](LINK_GRUB), [OMZSH](LINK_OMZSH)).

For the blog, though, **IBM ThinkPad** wins. It stays fast, works cleanly in light and dark mode, and stays distinct from my studio and art sites. Here we go.

### The Rebuild Plan

Instead of patching three-year-old HTML, I'm porting a clean Hugo pipeline I already battle-tested on a newer site and adapting it to the IBM ThinkPad aesthetic. Here is the checklist before the next post goes live:

- [ ] **Strip the 2023 relics:** Remove committed `public/` artifacts, stale `.devcontainer/` clutter, and broken asset paths from the repository.
- [ ] **Port the Hugo skeleton:** Set up clean `hugo.toml` and custom local `layouts/` with zero third-party theme submodules.
- [ ] **Enforce a test-first gate:** Add local and CI checks (`hugo --gc --minify --panicOnWarning`, internal link checks, and RSS XML validation) before anything deploys.
- [ ] **Wire GitHub Actions & Dependabot:** Deploy automatically to GitHub Pages on `main` and keep Actions dependencies patched via weekly Dependabot PRs.
- [ ] **Ship the ThinkPad skin:** Build lightweight, zero-JS CSS using `IBM Plex`, matte carbon / paper surfaces, TrackPoint-red accents, and full-text RSS (`/index.xml`).

Once the pipeline is green and the new theme is live, I'll follow up with the technical breakdown of how it came together.
